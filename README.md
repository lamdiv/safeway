# SafeWay

**See the signal. Review the evidence. Keep guidance current.**

SafeWay combines a source-monitoring board with an operator-supervised evacuation exercise. The monitoring page shows real Sentinel-2 catalogue timestamps, official NWS point alerts and provisional USGS gauge observations for Houston. It does not invent a flood-risk probability or interpret gauge height as depth at a building. Operator-reported assessment areas can recompute exposure against the historical Rasuwa assessed-point sample and create crossing review tasks.

The default Houston map uses OpenStreetMap vector streets and 3D building footprints through OpenFreeMap. The separate, optional water-level tool computes a continuous terrain-connected footprint from public Terrarium DEM tiles and screens visible OSM footprint centres. It is static screening, not a rainfall/runoff forecast, a depth estimate or a flow animation. The source is constrained to mapped river geometry, and missing terrain fails without substitution. Official NWS wind, heat and storm alerts are retained alongside flood alerts.

The Houston drill demonstrates the decision loop: **west route published → immediate withdrawal after closure → alternate withheld for missing evidence → current door update qualifies the east route → resident acknowledgement/check-in and separate SOS → end revokes sharing**.

Headwater is preserved on `main` at commit `6035fc2`. This implementation is on `safeway`. The Nepal animation remains optional legacy playback, with smooth connected terrain-path visuals; it is not the monitoring default or a physical flood model.

## Run

Node 22.13 or newer:

```sh
npm ci
npm run dev
```

The predev step prepares the official Matterport web component and its assets from pinned npm dependencies. No credential is embedded in the generated JavaScript. Copy `.env.example` to `.env` only if you do not already have local configuration.

- `/` — source/risk monitoring, with observed metadata and unknowns separated.
- `/operator` — Houston drill controls, approach qualification, missing facts, resident outcomes, SOS and event history.
- `/resident?invite=...` — single-use resident enrollment link generated by the operator.

Open **Resident links** in the operator view and use separate browser profiles/devices for Phone A and Phone B. Enroll both, start, pause, then use **Next event** for a deterministic demo. Each resident polls once per second and removes expired guidance while offline.

During development the preserved Headwater server can run independently with `node --env-file-if-exists=.env headwater-server.mjs`; it serves monitoring at `/` and Nepal playback at `/playback`. Use a different PORT when both servers run. The SafeWay server is the default server for this branch.

## Evidence and sponsor status

The credentials-free exercise property, approaches, flood geometry, participants, staff observations and indoor connection are **synthetic**. They are not renamed Nepal records or unverified sponsor data.

The **Sponsor data** action queries authorized Houston Matterport references and opens the official 3D web component. The API token stays server-side; the domain-restricted SDK key is supplied at runtime to its intended browser component. Use `localhost` for the supplied SDK domain allowlist. Marking a viewpoint does not verify a physical entrance, connecting path or current door state, and does not change route eligibility.

CoStar property joining and matched Vexcel approach evidence remain incomplete: the screenshot contains credentials and link labels, not the kit/quickstart target URLs. Vexcel's documented standard endpoints returned 401. Downloaded responses and credentials are private and excluded from Git. `docs/safeway/evidence-manifest.example.json` defines permitted reference metadata; the operator evidence intake stores it privately and does not silently approve it for guidance.

## Consent, access and persistence

Resident enrollment/session tokens are independent, run-specific and omitted from operator state/export. Operator endpoints require an operator bearer token or a local HttpOnly operator cookie. For phones on your LAN, set `HOST=0.0.0.0` and `SAFEWAY_OPERATOR_TOKEN`, then open the operator using your actual LAN address. The server refuses non-loopback exposure without an explicit operator token. This is a local exercise prototype, not a public identity service.

Stop Sharing clears active and related SOS coordinates and rejects later uploads. End revokes sharing, clears coordinates and prevents older worker results from publishing guidance. Actions and controls are idempotent. Local decision history is persisted without coordinates, tokens or resident identifiers under ignored `data/runtime/`. Active runs and sessions are in memory; restart creates a fresh run, and clients must not reuse expired directions.

## AI and delivery

The bounded LangChain Deep Agents supervisor can read/summarize evidence. It cannot decide eligibility, mutate an incident or publish guidance. Key-free explanation is labelled deterministic; actual SDK tool execution is tested with a scripted model. The live Bedrock smoke request returned ThrottlingException; successful live inference remains unverified.

The resident in-app receipt/open/acknowledgement/check-in/SOS flow is the demonstrated delivery path. The preserved Photon SMS/SIP adapters are not represented as verified SafeWay notifications. No real call, text, emergency dispatch or outreach has been performed. Tiger Data, push, QR check-in, foreground voice SOS and Vultr deployment are optional extensions, not claimed integrations.
